Fiddler

  1. Download and install Fiddler from https://www.telerik.com/download/fiddler
  2. Close all the browser windows opened
  3. Launch fiddler and go to Tools>Fiddler options, select the HTTPS tab and check Decrypt HTTPS traffic. You should now get some warnings related to the certificate installations, please click on OK and install the certificates.
  4. Once this is done, please clear the Temporary Internet Files from the browser for which we are collecting the Fiddler trace.
  5. Open a fresh browser window and access the application and once the issue is reproduced, note down the time so that we can narrow it down to that location.
  6. Save the log file. File>save>All sessions.

Fiddler on iOS

  1. Download Fiddler from https://www.telerik.com/download/fiddler
  2. Install Fiddler on a machine which is on the same domain and network as that of the mobile device.
  3. Click Tools > Fiddler Options > Connections.
  4. Click the checkbox by Allow remote computers to connect.
  5. Now, go to the HTTPS tab and enable Decrypt HTTPS Traffic option
  6. Restart Fiddler.
  7. Ensure your firewall allows incoming connections to the Fiddler process.
  8. Find the IP for the network that both devices are connected on (for ease make sure it's the same network)
    • One way to do this Hover over the Online indicator at the far right of the Fiddler toolbar to display the IP addresses assigned to Fiddler's machine.
    • Another is to go to wifi find the connection that both devices are connected on:
      • Click Properties
      • Scroll to the bottom where the network properties are listed.
      • Find the listing for IPv4 address.
  9. Verify client iOS device can reach Fiddler by navigating in the browser to http://FiddlerMachineIP:8888. This address should return the Fiddler Echo Service page.
    • Fiddler needs to be capturing for this to work. If Fiddler is not already capturing traffic, enable it by selecting File menu -> Capture Traffic and ensuring it's checked (alternatively you can also enable by hitting F12 or clicking on the lower left corner).
    • Replace the FiddlerMachineIP with the IP you located above. (for example http://123.45.67.89:8888)
  10. For iPhone: Disable the 3G/4G connection.

[iOS Setup]

  1. Before proceeding with these steps please confirm that you are getting the splash page when performing step 7 above
  2. To allow for HTTPS decryption we need to install Fiddler's certificate on the device this can be downloaded from the splash page when clicking the "FiddlerRoot certificate" link.
    • This step will need to be performed from Safari. From our testing and research, it seems that Apple only allows installation of certificates from Safari.
    • For more information on Fiddler's certificate please see their documentation https://docs.telerik.com/fiddler/Configure-Fiddler/Tasks/ConfigureForiOS
  3. After clicking you will get a prompt on whether you would like to allow the installation of the Profile. Select allow. Once installed you will get a second prompt notifying that the profile has been downloaded. This however does not mean that we have finished setting up the certificate.

  4. Next, go to Settings -> General -> Profile Management. Here you should see in the list an option under Downloaded Profile section DO_NOT_TRUST_FiddlerRoot. Select this to navigate to the install pane.
  5. After opening the profile click the Install button located in the top right. Once it's installed you should see the Not verified section below turn to a green Verified with a check mark and the title of the section should change from Install Profile to just Profile
  6. The final step to allow for https decryption, go to Settings -> General -> About -> Certificate Trust -> Settings and enable DO_NOT_TRUST_FiddlerRoot option.
  7. Now that we have HTTPS decryption set up change the Wi-Fi to use Fiddler as a proxy. Go to Settings -> Wi-Fi and select the information option next to the wifi that we are using.
  8. At the bottom, select to configure proxy. Once the page for Configure Proxy comes up choose Manual and enter the following details:
    • In Server field, enter the IP that we used in first section, Step 7.
    • In Port field, enter port number 8888.

[Data Collection]

  1. Before starting, prepare both the mobile device and the proxy machine for collection.
    • To try and minimize the data we capture please try to close out of all applications on both the proxy machine and mobile device that are not needed for the repro.
    • If there are any other tabs that are open, please close them.
  2. Clear the browser cache by going to Settings -> Privacy -> Clear browsing data and make sure the following are checked:
    • Cookies and site data.
    • Cache.
    • Form Data.
  3. Once checked click the button to clear browsing data.
  4. Now that we have the environments set for collection, start capturing traffic in fiddler.
    • If you had Fiddler capturing traffic during the set-up phase, please clear out any traffic not related to the issue at this time.
    • If Fiddler is not already capturing traffic, enable it by selecting File menu -> Capture Traffic and ensuring it's checked (alternatively you can also enable by hitting F12 or clicking on the lower left corner).
  5. Perform the steps necessary to reproduce the issue.
  6. Once finished, stop capturing traffic by repeating the above step.
  7. Save all sessions by selecting File menu -> Save -> All sessions...

[How to uninstall Fiddler Certificate once finished.]

  1. Go back to where we installed the Fiddler profile/certificate (Settings -> General -> Profile Management). Select DO_NOT_TRUST_FiddlerRoot
  2. Once inside the detail view for the profile press the Remove Profile button at the bottom.

netsh

  1. Make sure a temp folder exists at the root of C drive. If not, please create one.
  2. Close all Internet Explorer windows
  3. Open an elevated command prompt (Run as Administrator) and run the following command: ipconfig /flushdns
  4. Once flushdns completes, start tracing by typing the following command:

    netsh trace start tracefile=c:\temp\internetclient.etl scenario=InternetClient_dbg level=5 capture=yes persistent=yes

  5. If it is server machine, then from Run window, open iexplore.exe about:blank. Else, open Edge to access the URL in IE Mode.
  6. Access the impacted URL.
  7. If the issue happens then, stop tracing, by typing the following command:

    netsh trace stop

  8. If the issue does not reproduce, then also stop the tracing using following command and start again from Step 2:

    netsh trace stop

  9. It will generate few files under C:\Temp, out of them please share the .etl, and .cab files for analysis. Other files may not be produced for a variety of reasons, getting the ETL file is the essential piece of data.

Note for Engineer

If the issue is not specific to a URL, then we should always use example.com to collect the logs. It generates least amount of traffic, so the log becomes light weight with lesser noise and easy to analyze.

Crash Dumps - Generic

  1. Create a new folder under C drive called Dumps.
  2. Open Registry Editor.
  3. Go to HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps.
  4. Right click on LocalDumps and select New> DWORD.
  5. Name it as DumpType and set the value as 00000002.
  6. Right click on LocalDumps and select New> DWORD.
  7. Name it as DumpCount and set the value as 0000000a.
  8. Right click on LocalDumps and select New> String Value.
  9. Name it as DumpFolder and set the value as C:\Dumps.
  10. Perform the steps to reproduce the crash and once the issue happens, a crash dump should be created in the folder specified above.

Alternatively, we also can use the following method:
  1. Open an elevated command prompt (i.e., with administrative privileges) and type the following commands:

    • reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps" /v DumpFolder /t REG_EXPAND_SZ /d "C:\Dumps" /f

    • reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps" /v DumpType /t REG_DWORD /d "2" /f

    • reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps" /v DumpCount /t REG_DWORD /d "10" /f

  2. Create a new folder under C drive called Dumps (or other folder you specified in the reg add command above) if the folder does not exist.
  3. Perform the steps to reproduce the crash and once the issue happens, a crash dump should be created in the folder specified above.

If the dumps are not generating, then we can check if Windows Error Reporting service is already started (the service name is WerSvc). We may need to restart it, so the new registry configurations are read appropriately.

Note for Engineer

This configuration for Windows Error Reporting will collect full memory dumps if any process crashes. It should be used when we are not sure about the name of the exe, but we are sure that the crash is happening. Some examples could be cases where we are using Web Browser Control, but we are not sure about the exe name, we suspect that the issue could be because of third-party crash but we are not sure which exe could be causing it etc.

Crash Dumps - Process Specific

  1. Create a new folder under C drive called Dumps.
  2. Open Registry Editor.
  3. Go to HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps.
  4. Right click on LocalDumps and select New> Key.
  5. Name the key as process_name.exe.For example, if we want to capture crash dumps for Internet Explorer only, then we should name the key as iexplore.exe.
  6. Right click on process_name.exe and select New> DWORD.
  7. Name it as DumpType and set the value as 00000002.
  8. Right click on process_name.exe and select New> DWORD.
  9. Name it as DumpCount and set the value as 0000000a.
  10. Right click on process_name.exe and select New> String Value.
  11. Name it as DumpFolder and set the value as C:\Dumps.
  12. Perform the steps to reproduce the crash and once the issue happens, a crash dump should be created in the folder specified above.

Alternatively, we also can use the following method:
  1. Open an elevated command prompt (i.e., with administrative privileges) and type the following commands:

    • reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\process_name.exe" /v DumpFolder /t REG_EXPAND_SZ /d "C:\Dumps" /f

    • reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\process_name.exe" /v DumpType /t REG_DWORD /d "2" /f

    • reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\process_name.exe" /v DumpCount /t REG_DWORD /d "10" /f

  2. Create a new folder under C drive called Dumps (or other folder you specified in the reg add command above) if the folder does not exist.
  3. Perform the steps to reproduce the crash and once the issue happens, a crash dump should be created in the folder specified above.

If the dumps are not generating, then we can check if Windows Error Reporting service is already started (the service name is WerSvc). We may need to restart it, so the new registry configurations are read appropriately.

Note for Engineer

This configuration for Windows Error Reporting will collect full memory dumps if any process crashes. It should be used when we are not sure about the name of the exe, but we are sure that the crash is happening. Some examples could be cases where we are using Web Browser Control, but we are not sure about the exe name, we suspect that the issue could be because of third-party crash but we are not sure which exe could be causing it etc.

Crash Dumps - Using ProcDump

  1. Download Procdump utility from https://docs.microsoft.com/en-us/sysinternals/downloads/procdump
  2. Create a folder under C drive and name it as Dumps.
  3. Extract ProcDump to C:\Dumps folder.
  4. Open command prompt as Administrator and cd to C:\Dumps.
  5. Run this command procdump -ma -i c:\dumps.
  6. Close command prompt and wait for the issue to happen.
  7. Once the issue happens, it would generate the dump files under C:\Dumps folder.
  8. After the dumps are collected, we should always uninstall procdump as the default debugger. Run this command procdump -u to disengage the debugger.

As soon as you set this utility as default debugger using the command, there is no user or administrator intervention needed.

Hang Dumps

  1. Determining the Process ID using Process Explorer (If hanging process is iexplore.exe):
    • Download and run Process Explorer from https://live.sysinternals.com/procexp.exe.
    • Once it is up and running open Internet Explorer and try to replicate the issue.
    • As soon as the issue happens, come back to Process Explorer
    • Click and hold the target icon and drop it over the Internet Explorer window which is in hung state. This would highlight the iexplore.exe process relating to the hung tab. Make a note of the PID of iexplore.exe highlighted. We will use it while collecting hang dumps.

  2. Determining the Process ID using Browser Task Manager (If hanging process is msedge.exe):
    • a. Keep a separate Edge process opened which we would use to open Browser Task Manager.
    • b. Click on the three dots menu and select More Tools> Browser Task Manager. A window like this would appear. Keep it open.
    • Open another Edge window and then reproduce the issue there. Once the issue has happened, take note of the Process ID where the hung page loads.

  3. Collecting Hang Dumps:
    • Download and Extract ProcDump utility from https://live.sysinternals.com/procdump.exe and save it under C:\Temp folder.
    • Open command prompt as Administrator.
    • Cd to C:\Temp where we have extracted ProcDump
    • Once done, run the following command once browser window goes into hung state, to gather the hang dump:

      Procdump -h -ma pid

    • Replace pid with the Process ID determined earlier in the process.
    • Hit Enter and it will automatically collect a dump.
    • In case, you do not see any message saying dump is generated then run the following command:

      Procdump -ma pid

    • Collect three such dumps in an interval of 30 seconds each.

Note for Engineer

  • These logs should be collected very carefully. If we fail to follow these steps, we might end up having incorrect data, which would lead to collecting the data again. So, always go through the steps and if possible, always collect hang dumps in our presence unless the issue is intermittent. If we cannot be on the call, make sure we educate the customer through the complete process of collecting the dumps so that we get the right data.
  • Also, the interval specified in the steps is 30 seconds. However, if the hang does not last for more than a minute then just divide the length of hang by 3 and decide the interval the dumps should be collected. For example, if the hang lasts for 30 seconds, then 10 seconds should be chosen as the interval to collect the dumps.
  • In the hang scenario, we should always collect at least three dumps. Collecting just one or two dumps would not be useful, as they would not give us the correct information around the hung threads.

Windows Performance Recorder (WPR) - Leak

  1. Download the Windows ADK version matching the Windows version where the problem occurs at https://aka.ms/adk (for Windows 7 use the Windows 8.1 ADK package).
  2. Select the Windows Performance toolkit only for installation.
  3. Gathering performance traces instructions:
    • To collect the traces, use Windows Performance Recorder (type wpr in the start menu search and then select Windows Performance Recorder).
    • Enable the following options:
      • First Level Triage
      • CPU Usage
      • Heap Usage
      • VirtualAlloc Usage


  4. Click start in WPR. Navigate to the reproduce the issue on the browser.
  5. Repeat the leak cycle three times without closing the browser.
  6. Once you can reproduce the issue, stop, and save the trace.

Note for Engineer

Before we start collecting the logs, make sure we have closed all the applications other than the required ones because WPR would collect data from all the running processes, making it a heavier log. This could result in upload issues, problems while analyzing etc.

  1. Clear the Temporary Internet Files and close all the instances of Internet Explorer or IE Mode windows opened.
  2. Open a fresh instance of Internet Explorer/IE Mode.
  3. If we are using standalone Internet Explorer, then press F12 key and F12 developer tools would appear on the screen. Alternatively, we can also go to Settings> F12 Developer Tools to open F12 Developer Tools.
  4. If we are accessing the site in IE Mode, the go to C:\Windows\System32\F12 location and start IEChooser.exe. In the launched window, select the tile that shows the tab/site we want to capture the log for.
  5. Once it is opened, go to the Network tab.
  6. By default, it would be in Capturing mode. If it is Stop button would be enabled and the toolbar would look like this:

  7. If it does not load in this mode, click on the green Play button and it starts capturing.
  8. Carry out the steps to reproduce the issue.
  9. Once the issue is reproduced, click on the Stop button on the F12 Network tool.
  10. Click on Save button to save the capture.
  11. File should be saved with .har extension.

Note for Engineer

There is an option on F12 Network tool called Clear entries on navigate and it stays enabled by default. If we are capturing a log from a scenario where multiple redirections would happen, then we should always disable this option before capturing the log. Else, Network tool would clear the entries as soon as navigation happens.

gpresult

  1. Open command prompt as Administrator.

Time Travel Trace using WinDbg - Edge

  1. Download and install WinDbg from https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/.
  2. Once installed, run WinDbg as Administrator.
  3. Now, close all the opened Edge windows. Then go to Task Manager > Details, and from there kill all the running msedge.exe processes.
  4. Open a fresh instance of Edge and click on Settings> More Tools> Browser Task Manager.
  5. Make a note of the PID of Edge process we are interested in.


  6. Close Browser Task Manager.
  7. Go to WinDbg and click on File menu and then under Start debugging section, click on Attach to process.
  8. In the search box at the top right corner, key in the PID of the Browser process. Select the process.


  9. Then enable the option that says Record with Time Travel Debugging.
  10. Once we have WinDbg configured for the desired Edge process, we need to perform the following steps on WinDbg:
    • Click on Configure and Record button.
    • We will get a pop-up called Configure Recording.
    • Browse the location where we want to save the output file and click on Record.

    • It will say Intializing.
    • Once it starts recording on both the instances, go back to Edge, and reproduce the issue.

  11. After we have reproduced the issue, click on Stop and Debug button.
  12. The trace will be saved under the location we have selected earlier.

There are few points that we need to make sure of while collecting Time Travel Traces, and they are as following:

  • Close all the other applications that are not needed to reproduce the issue. The reason is, Time Travel Trace is a very verbose trace, and it could consume and need more memory. If there are multiple applications running, it might fall short of memory and stop recording or crash, which would not give us the correct data that we are looking for.
  • Do not open additional tabs on Edge. Try to keep just one tab active and reproduce the issue on that tab only.
  • We need only the recording of the issue and nothing else. So, it is good to launch Edge and go to about:blank on the tab, which will load a blank page. From here, we can type in or paste the URL in question and reproduce the issue.
  • If for any reason, issue replication or log collection breaks, we need to start over with the logs collection process highlighted above. Few examples would be, WinDbg closes, Edge closes, we get some unexpected error while accessing the site, we typed in a wrong URL etc.
  • Once we have clicked on Configure and Record, do not close Edge. Keep using the same one, else PID will change, and the tracing will stop giving us incorrect data.
  • Administrative privileges will be required to be able to Attach to a process.

Note for Engineer

  • There would be two files generated with .out and .run extension. We would need both the files.
  • Process ID determination is very important while capturing TTT. So, make sure we have the right Process ID before attaching the debugger.

Time Travel Trace using TTTracer.exe - Edge

  1. Download the TTTracer package from the secure workspace. You can find the file by the name PartnerTTDRecorder_x86_x64.zip.
  2. Extract the content of the zipped file. You will find two versions of the tracer, 64bit and 32bit. We would need to make use of the exe in accordance with the Operating System bitness.
  3. Now, close all the opened Edge windows. Then go to Task Manager > Details, and from there kill all the running msedge.exe processes.
  4. Open a fresh instance of Edge and click on Settings> More Tools> Browser Task Manager.
  5. Make a note of the PID of Edge process we are interested in.


  6. Close Browser Task Manager.
  7. Run Command Prompt as Administrator and go to the location where we have TTTracer.exe.
  8. Once done, we would have to initialize the Tracer by running this command - TTTracer.exe -initialize
  9. Run this command to attach the utility with the process - TTTracer.exe -dumpFull -attach PID. Replace the PID part of the command with the Process ID determined in Step 5.
  10. You will see a small window with Exit App button on it and the name of the exe on the title. If you can see this, it means that the tracer has been successfully attached to the process.
  11. Reproduce the issue on the opened browser window.
  12. Uncheck the tracing option on the TTT window.
  13. Go to the folder from where we have used TTTracer.exe and check if we get two files with the extension .out and .run.
  14. If yes, upload them to the workspace.

There are few points that we need to make sure of while collecting Time Travel Traces, and they are as following:

  • Close all the other applications that are not needed to reproduce the issue. The reason is, Time Travel Trace is a very verbose trace, and it could consume and need more memory. If there are multiple applications running, it might fall short of memory and stop recording or crash, which would not give us the correct data that we are looking for.
  • Do not open additional tabs on Edge. Try to keep just one tab active and reproduce the issue on that tab only.
  • We need only the recording of the issue and nothing else. So, it is good to launch Edge and go to about:blank on the tab, which will load a blank page. From here, we can type in or paste the URL in question and reproduce the issue.
  • If for any reason, issue replication or log collection breaks, we need to start over with the logs collection process highlighted above. Few examples would be, WinDbg closes, Edge closes, we get some unexpected error while accessing the site, we typed in a wrong URL etc.
  • Once we have clicked on Configure and Record, do not close Edge. Keep using the same one, else PID will change, and the tracing will stop giving us incorrect data.
  • Administrative privileges will be required to be able to Attach to a process.

Note for Engineer

  • There would be two files generated with .out and .run extension. We would need both the files.
  • Process ID determination is very important while capturing TTT. So, make sure we have the right Process ID before attaching the debugger.
  • TTTracer package could be availed from \\sesdfs\1Windows\TestContent\ES\dbg\privates\lkg\partner location. Upload it on DTM, and once you have successfully collected the logs, delete it from customer's machine and DTM both.
